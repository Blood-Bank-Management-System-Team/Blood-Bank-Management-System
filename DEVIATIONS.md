# Deviations from SRS / SAD / Test Plan

This file records every place where the current BBMS implementation differs from the submitted Team 9 documents (SRS v1.0, SAD v1.0, Test Plan v1.0, Project Proposal). It is kept for the final demo so evaluators can see what was changed, added or postponed, and why. Last updated: 2026-10-28.

Scope of this review: code on the current branch (BB-01 skeleton, BB-02 CI, BB-03/BB-04 authentication, BB-05/BB-06 donor registration and eligibility, BB-11 blood request submission, plus the inventory API and BB-13 role dashboards). `users`, `donors`, `inventory` and `bloodrequests` have real logic; `camps`, `notifications` and `reports` are still empty scaffolds. `backlog.csv` does not exist in the repo, so backlog mapping is limited to the items named above. Reasons are only filled in where they are visible in the code or task descriptions; everything else says "To be confirmed by team".

Most important deviations:
- Frontend is server-rendered Django templates, not HTML/CSS/JS or React talking to the REST API (DEV-02).
- Registration works without OTP verification and without admin approval, and STAFF/ADMIN cannot self-register (DEV-03, DEV-04, DEV-05).
- Configurable rules (BR-3) are environment variables for now, not administrator-editable settings (DEV-06).
- Four SAD modules (Search & Matching, Administration, Certificates, Audit Logging) have no dedicated app yet (DEV-07).
- Donor registration is a separate step after account sign-up, and eligibility is a simple rule set computed on the fly with no donation history or reminders yet (DEV-17 to DEV-19).
- CI and a CD pipeline (GitHub Actions) exist, and HTTPS settings are enforced when DEBUG is off, but neither has been exercised on a real server yet, and the Test Plan's Postman/JMeter tooling is not set up (DEV-13, DEV-14, DEV-16).

## Test Plan differences

- **Planned test case IDs not automated:** TC-INV-01 to TC-INV-08, TC-REQ-05, TC-REQ-07, TC-PERF-01/02, TC-SEC-01 to TC-SEC-04, TC-DATA-01/02, TC-AUD-01 and TC-SAF-01 to TC-SAF-04 have no matching code, because the features they test are not built yet. Appendix A cases (TC-REQ-05 compatibility, TC-INV-04 expiry, TC-DATA-01 concurrent allocation) are also not automated.
- **Automated now:** 70 tests across the repo, all passing. `users/tests.py` has 17 (health, home page, default role, hashed password, API registration/role restriction/weak password/login/refresh/wrong password/`me`, dashboard redirects and 403, web registration). `donors/tests.py` covers FR4, FR6 and BR-2 (eligibility rules, settings overrides, profile and eligibility APIs, permissions, validation, dashboard badge); `inventory` and `bloodrequests` have their own tests. Together they partly cover FR1, FR4, FR6, NFR5, NFR6 and NFR7. They are not labelled with Test Plan IDs, and the Test Plan does not define TC-SEC-01 to TC-SEC-04 in detail, so the mapping is to be confirmed by team.
- **Tooling:** Postman/Newman, JMeter, UI smoke tests and coverage metrics are not set up (DEV-16). Local tests run on SQLite; CI runs them on PostgreSQL (DEV-10, DEV-13).
- **Not planned in code yet:** SQL injection/XSS tests, HTTPS verification, concurrency tests (NFR20/NFR21) and notification stubs.
- **Document inconsistency:** the Test Plan introduction calls the system "BBMS v2.0" while the SRS and SAD are version 1.0. To be confirmed by team.
